## v3.8.1 (2026-10-28) — 실시간 공고 수집 정상화

v3.8.0 운영 배포 직후 `/programs` 응답이 **10건**(기업마당 0 · K-Startup 10)이었던 문제.

| 원인 | 조치 |
|---|---|
| 기업마당 500건 응답이 소스별 7초 제한 안에 오지 않음(`The operation was aborted due to timeout`) | 수집을 시간 제한이 긴 함수로 분리 — `refresh-programs-scheduled`(30분마다, 30초)·`refresh-programs-background`(필요 시, 15분). 결과는 Netlify Blobs 스냅샷 |
| K-Startup API는 `page`·`perPage`를 쓰는데 `numOfRows`·`pageNo`로 요청 → 기본 10건만, 페이지도 모두 같은 10건 | `page`·`perPage` 사용(두 이름 함께 전송), 100건 × 5페이지 |
| 일부 소스 실패 결과도 CDN에 30분 캐시 | 오류 없는 결과만 CDN 캐시(10분), 부분 결과는 스냅샷에 저장하지 않음 |

`programs`는 스냅샷을 읽어 바로 응답하고(마감 공고는 응답 시점에 다시 제외), 스냅샷이 45분보다 오래되면 백그라운드 갱신을 요청합니다. 수집 함수는 20분 안에 갱신한 스냅샷이 있으면 아무것도 하지 않아 반복 호출로 쿼터를 쓰지 못합니다.
