# 지원사업 MATCH v3.7.0 자가부검 · 레드팀 점검 (2026-10-28)

대상: 라이브 배포본 v3.7.0(`index.html` + `app2.js` + `data.js` + Netlify 함수 5개)과 데모 단일본(`index_3.html`, 같은 코드를 인라인한 파일) · 조치 버전 v3.8.0

## 점검 방법

| 방법 | 내용 |
|---|---|
| 엔진 재현 | 원본 `app2.js`를 Node VM에 올려 DEMO 16건 × 유형별 프로필로 판정 결과·근거 문구를 덤프 |
| 원본 화면 재현 | 원본 폴더를 정적 서버로 띄워 Chromium으로 4개 유형 흐름·변조된 임시저장·모바일 375px 확인 |
| 악성 데이터 | 공고명·기관·금액 문구·설명·문의·우대·URL·공고 ID에 HTML·`javascript:` 주입 |
| 서버 함수 | 공개 엔드포인트별로 외부 호출 횟수·쿼리 조작·응답 크기·마감 판정 시각 검토 |
| 문구·근거 | 화면 숫자가 계산값과 맞는지, 과장·검증 불가 표현, 개인정보 안내와 실제 동작 일치 |

## 확인했지만 결함이 아닌 것

- 기업 입력값은 `programs` 요청에 실리지 않음(GET, 파라미터 없음) — 서버 전송 없음이 사실
- `health` 함수는 키 설정 여부만 반환하고 값은 반환하지 않음(사용하지 않는 `NTS_API_KEY` 항목만 정리)
- 모바일 375px 결과 화면 가로 넘침은 원본에서도 재현되지 않음
