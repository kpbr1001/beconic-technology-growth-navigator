# CHANGELOG — 고객문제·솔루션 적합성 진단 (Tool 20)

## v2.0 (2026-11-19) — Phase 1 진단 신뢰성

화면 구성·방법론(Double Diamond·JTBD·VPC·Lean·Kano)·문항·17섹션 보고서·PDF 등 v1.5의 장점은 유지하고, 그 아래 점수 엔진을 다시 만들었습니다.

### 진단 대응표 (v1.5 점검 결과 → v2.0)

| # | v1.5 문제 | v2.0 대응 |
|---|---|---|
| 1 | 점수가 '입력 여부·글자 수'로만 결정 — 서술 칸을 '아아아…'로 채워도 **100점 S등급** | 품질가중 채점(작성법 체크 신호 충족률). 같은 입력이 **15점·신뢰도 0·판정 보류 권고**로 바뀜 |
| 2 | 문장 품질 분석(`analyzeText`)·정합성(`conceptOverlap`)이 있었지만 보고서 문장에만 쓰이고 점수엔 미반영 | 품질·정합성을 점수 산식에 반영. 정합성은 별도 영역(10점) |
| 3 | 문제↔솔루션 연결을 측정하지 않음(적합성 진단인데 적합성 미측정) | 5개 연결 구간 점검. 문제와 무관한 솔루션(HR앱)을 넣으면 정합성 1/10·69점 상한·'정합성부족형' |
| 4 | 검증근거 10점, 인터뷰 15명과 유료 매출이 같은 2점 | 20점으로 상향, 증거 등급 L0~L6·등급 관문(S=L5, A=L3, B=L1) |
| 5 | 서로 맞지 않는 응답(유료 고객 있음·매출 없음, '성장' 단계·매출 없음)을 그대로 수용 | 모순 탐지 9종 → 감점·상한·신뢰도 반영, 화면·보고서에 '점검 사항'으로 공개 |
| 6 | 예비창업자와 매출 기업을 같은 잣대로 판정 | 사업단계별 기대수준(아이디어 48 ~ 스케일업 85점) 비교, 막대마다 기대선 표시 |
| 7 | 'AI 진단' 표기였지만 실제 LLM 호출 없음 | '규칙 기반 사전진단'으로 정정(AI 해석은 Phase 2에서 선택 기능으로 추가 예정) |
| 8 | 판정 임계값이 배점에 하드코딩(`sc.validationEvidence<6` 등 21곳) | 만점 대비 비율(`RT()`)로 전환 — 배점을 바꿔도 판정 유지 |

### 문항 작성 가이드
- 40개 문항 모두 **작성법(공식) · 좋은 예 · 피할 예(이유)** 표시. 서술 30개 문항은 **실시간 작성 체크**(✓ 대상 ✓ 수치 …, 보강 필요/양호/우수).
- 작성법 체크 신호 = 채점 신호(`GUIDE.checks`). QA가 "좋은 예는 모든 체크 통과, 피할 예는 0.6 미만"을 매번 확인.
- 샘플 데이터를 작성법대로 다시 씀(사업단계 '시제품'으로 정정 — v1 샘플은 '초기매출'인데 매출 없음이라 모순).
