# v0.6.1 — 실배포 결과(v0.6.0) 기반 조정 (대표 결정 A~C)

실배포 확인(대표 입력 그대로, 실물 제품 선택): 이름은 브랜드형으로 개선(멘토저울·로드싱크·경영짝꿍·IR한장·딜체커)됐으나

| # | 결정 | 조치 |
|---|---|---|
| A | 실물 제품 엄격 처리 | 실물 제품 = Product 만(제품+서비스 제외), 기기 = Hardware. CALL A·B에 "물건을 파는 구조, 소프트웨어·자문으로 바꾸지 말 것" 명시, 정의에 물건(키트·세트·기기 등)이 없으면 서버가 정의를 교정. 형태별 예비 후보를 문제당 2개 더 남겨 교체 가능하게 |

# v0.9.0 — 지식iN·블로그·뉴스·쇼핑인사이트 연동 (NAVER API HUB 가이드 4종)

| API | 호출 | 쓰는 값 | 근거 인정 기준 |

- 화면: '사람들이 이 문제를 이야기하나요?'(지식iN 질문·블로그·뉴스) + 쇼핑 분야 흐름, PDF 데이터 표에 열 추가.

- 다른 이름 후보 = [조어형 1, 전문 서술형 1]

# v0.9.2 — 실배포(v0.9.1) 데이터 품질 점검 결과 반영
실제 결과: 이름 개선(그로스핏·코어진·셀패스·스타트핏·밸리데이) 확인. 그러나
1. **검색 추이 5개 모두 공백** — 호출은 성공. 네이버가 검색량 0인 달을 빼고 돌려주면 36개월 미만이 되어 결과를 버림 → 기간 전체 달을 만들고 빈 달은 0으로 채워 계산
2. **지식iN·블로그·뉴스 근거 과대평가(전부 L2)** — 일반 검색어 하나로 조회해 무관 결과("중소기업 건강검진", "표현의 자유")까지 셌고, 블로그·뉴스는 모두 '100건 이상'으로 포화
   → 관련도 필터(검색어 핵심 단어가 제목·요약에 모두 있어야 관련), 지식iN 표본 20건 중 관련 5건 이상일 때만 근거 인정, 블로그·뉴스도 관련 글만 계산
   → CALL A가 문제마다 전용 '고객 질문형 검색어(voiceQuery)' 생성(다른 뜻과 섞이는 일반어 금지)
   → 화면: "관련 질문 8/20건", 기준 미달은 "판단하지 않았어요"로 표시
3. 이름 끝 글자 겹침(그로스핏·스타트핏) → 같은 끝 글자는 다른 후보 이름으로 교체
