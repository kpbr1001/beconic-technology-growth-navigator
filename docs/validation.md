# 검증 체계 (v0.9.21~)

결과가 "깨지지 않는지"(기존 단위·E2E·PDF 검수)에 더해, 결과가 "맞고 일관된지"를 확인한다. 1차는 코드로 매번 확인하는 자동 검증이다.

## 1층 자동 검증

| 장치 | 위치 | 무엇을 막나 | 실행 |
|---|---|---|---|
| 논리 검증(성질 테스트) | `tests/unit/properties.test.ts` | 공식의 모순(응답↑인데 점수↓, 규모·업력이 점수에 영향, '모름'이 1점보다 불리 등) — 무작위 입력 300건 | `npm test` |
| 표준 사례 12개 기대 결과표 | `tests/fixtures/golden.ts`, `tests/golden/golden-cases.md` | 규칙 변경으로 결과(P0·추천안·기술 1위·R&D·보완 후보)가 조용히 바뀌는 것 | `npm test`, 의도한 변경이면 `npm run golden:update` 후 표 검수 |
| 문장 품질 자동 검사(v0.9.24) | `src/reports/text-quality.ts` | 조사 병기('이(가)')·조사 불일치·내부 문항 코드(Q9)·영어 내부 용어·같은 칸 반복·170자 넘는 문장 | E2E에서 13사례의 화면·PDF 모든 쪽 |

### 논리 검증 성질 (모두 통과)
1. 응답을 올리면 그 영역 점수·기술역량이 내려가지 않음
2. 근거자료 수준을 올리면 진단 신뢰도가 내려가지 않음
3. 기업규모·업력·단계·기업명은 점수·우선순위·추천안에 영향 없음
4. '모름'은 같은 문항 1점 응답보다 영역 점수가 낮지 않음
5. 공통 핵심 8문항 미만이면 전부 판단 보류
6. 점수·신뢰도 범위, 오차 범위가 기술역량을 포함
7. 우선순위 정렬 P0→P1→P2(같은 등급은 점수 낮은 순)
8. 영역 응답을 올려도 그 영역 우선순위가 더 급해지지 않음
9. 근거 보강으로 추천안이 B·C → A로 되돌아가지 않음
10. 기술에 확인 항목을 더 채우면 순위가 내려가지 않음
11. R&D·보완 대조·순위는 핵심기술만, 보완 후보는 원문 핵심기술 안에서만
12. 핵심기술 3개 이상이면 R&D 과제마다 다른 기술

### 보고서 정합성 검사 항목(21)
요약 최우선 과제 = 90일 계획 첫 과제 · 90일 계획 P0→P2 · 격차표 = 90일 계획 · 1분기 로드맵 = 최우선 과제 · 요약 '먼저 검토할 기술' = 핵심기술 1위 · 로드맵 대조표 순서 = 기술 순위 · R&D 기술 ⊂ 핵심기술 · 기술 표 '연결 과제' = R&D 쪽 · 보완 대조 자사 기술 ⊂ 핵심기술 · 히트맵 건수 = 리스크 표 · 성과지표 '높음' 수 = 레드팀 · 추천안 = 의사결정 요청 · 점수표 = 레이더 · 쪽 번호 연속·총 쪽수 · 쪽 참조 정확 · 깨진 값·미치환 표식 없음 · 신청 준비도 종합 판정 = 관점·자격 판정 · 바우처 근거 리스크 = 레드팀 표 · 세부 항목 레이더 = 표 · 관점 판정 = 항목 규칙 · 핵심요약 = 본문(최우선 과제·핵심기술 1위·신청 준비도·'높음' 리스크·역량 점수)

## 1차 검증에서 바로 고친 것
- 보완 필요 기술 대조: 한 단어만 겹쳐도 '보유'로 판정(예: '코인셀 수명 평가' ↔ '장수명 전극 소재') → 2단어 이상 겹침만 '보유', 1단어는 '일부 겹침 — 원문 대조 필요'.

## 지원사업 신청 준비도 기준(v0.9.22, 시범 — 전문가 검증 대상)
| 관점 | 충족 | 미흡 | 그 외 |
|---|---|---|---|
| 기술성 | 핵심기술 1위 TRL 3~7 · 차별 요소(Q12) 4점 이상 · 근거 '추적 기록' 이상 | 핵심기술 없음·TRL 미확인·Q12 2점 이하/모름 | 보완 |
| 수행 역량 | R&D 역량 60↑ · 기술기록 55↑ · 핵심 인력 리스크 '높음' 아님 | R&D 45 미만·기술기록 40 미만·연구전담조직 없음 | 보완(점수 없으면 확인 필요) |
| 사업화·검증 | 실제환경 검증(Q2) 4점↑ · 검증 경험 입력 | Q2 2점 이하/모름 그리고 검증 경험 없음 | 보완 |
| 정책 연계 | 원문 색인 품목 후보 · Q11 3점↑ · 핵심기술 로드맵 연결 | 품목 단위 후보 없음 | 보완 |
- 보완할 점(코멘트)이 하나라도 있으면 '충족'으로 두지 않는다.
- (v0.9.23) 기술성·수행 역량은 5개 세부 항목(0~100점, 70↑ 충족·45↑ 보완·미만 미흡·입력 없음 확인 필요)으로 판정: 필수 항목 미흡 → 미흡 / 확인 가능 항목 3개 미만 → 확인 필요 / 평균 45 미만 → 미흡 / 평균 70↑이고 보완·미흡 항목 없음 → 충족 / 그 외 보완. 관점 점수 = 확인 가능 항목 평균.
  - 기술성: 기술 성숙도(필수, TRL 3~4=70·5~7=90·8~9=60·1~2=30·미확인 0) · 차별성(필수, Q12, 근거 '내부 자료' 이하면 60점 상한, '모름'은 확인 필요이며 관점 미흡) · 핵심 기능 구현(Q1+업종 심화 기술 문항 평균) · 로드맵 핵심기술 연계(원문 핵심기술 중 보유 1개 70점·1개당 +10, 일부 겹침 50, 답변 언급 35, 없음 20) · 지식재산 보호(R5 낮음 85·중간 55·높음 30)
  - 수행 역량: 연구 자원(Q3) · 개발·검증 반복(Q4+심화 R&D 문항) · 과제 관리(실행준비) · 기술 기록(기술기록) · 연구 조직·인력(필수, 연구소 90·전담부서 75·없음 20, 연구 인력·R3로 가감, 미입력 확인 필요)
- 종합: 판단 보류·'미흡' 관점·자격 '결격 가능성' → 선행 조건 필요 / 모두 충족 → 신청 준비됨 / 그 외 보완 후 신청.
- 자격 확인 8항목(연구전담조직·연구 인력·체납·채무불이행·참여제한·수행 중 과제·자부담·인증)은 선택 입력이며 점수·우선순위에 쓰지 않고 AI에 보내지 않는다(논리 검증으로 확인).
