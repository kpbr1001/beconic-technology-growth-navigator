# v2 시안 자체 검토·레드팀 결과 (2026-11-22)

원칙: **쉽게**(버튼 한 번, 쉬운 말) · **정확하게**(공식 근거 숫자·입력과 판정 일치) · **명확하게**(결론 먼저, 모르는 건 모른다고)

## 1. 발견 → 수정 (시안에 반영 완료)

| # | 구분 | 발견한 문제 | 위험 | 수정 |
|---|---|---|---|---|
| 1 | 정확 | 결과 첫 줄 "지금 신청할 수 있어요" | 기관 평가가 남았는데 취득 가능처럼 읽힘 | "신청 **기본요건을 갖췄어요**" + "심사 결과는 기관이 결정" |
| 2 | 정확 | 연구개발비 비율 칩 5~8%/8~10% | 업종·매출별 기준(5·6·7·8·10%)과 경계가 어긋나 오판 가능 | **우리 회사 기준값을 자동 계산해 "10% 이상인가요?"** 한 질문으로 |
| 3 | 정확 | 매출 칩 10억·50억·100억 | 공식 비율표 구간(50억·100억)과 불일치, '연 매출' vs '직전 4개 분기' 혼동 | "직전 4개 분기 매출: 50억 미만/50~100억/100억 이상" |
| 4 | 정확 | 회사 규모 "소기업"만 표시 | 인원 기준으로 착각(실제는 매출·업종 기준) | "중소기업확인서의 구분" 안내 + 모름 |
| 5 | 정확 | 이노비즈 "2가지 확인하면 판정" | 그중 1개(별표 2)는 운영사도 원문 미확보 — 고객이 확인해도 판정 불가 | "확인 필요 2개(1개는 공식 원문 미확보)" + 협회 연락처 |
| 6 | 정확 | 할 일 "체납 없으면 요건 대부분 충족" | 과장 | "체납 여부·신청 불가 업종 확인" 사실만 |
| 7 | 정확 | 사회적기업 '자동 판정' 표시 | 아직 규칙 미검증 | '요건 체크'로 표시, 검증 후 상향 |
| 8 | 정확 | 신청서류 "8개"인데 표 6줄, 가이드라인 PDF를 서류로 셈 | 숫자 불일치 | 가이드라인은 '공식 안내'로 분리, 8개 모두 표시(접기 포함) |
| 9 | 명확 | 요약 칸 구성이 카드마다 다름(유효기간/신청처) | 비교 어려움 | 모든 카드 **기본요건 · 신청서류 · 신청처** 고정, 유효기간은 근거 있을 때 상세에 |
| 10 | 명확 | "요건 5/5"인데 목록 6줄(평가·해당 없음 포함) | 셈법 혼란 | "기본요건 (평가 제외) 4/4 충족" 표기 |
| 11 | 명확 | "약 30초 남음" | 근거 없는 시간 | 삭제("14개 중 10개 답함"만) |
| 12 | 명확 | 근거 조항 누락 | 신뢰 저하 | 연구소 기준에 "시행령 제6조", 사후관리에 "운영규정 제12조·시행규칙 제8조" |
| 13 | 쉽게 | 모바일 가로 넘침(445px), 하단 바 버튼 중복 | 사용 불편 | 수정(390px 맞춤, 버튼 1개) |

## 2. 신청서류·공식 링크 (요청 1)
- 화면 '신청서류' 탭 + PDF '04 신청서류와 공식 링크' 쪽: **서류 · 왜 필요한가 · 발급·내려받기 공식 주소 · 보유(자가응답)**
- 공식 서식은 **링크로 제공**(파일 재배포 안 함 — 서식 개정 시 낡은 파일이 퍼지는 위험, 저작권)
- 확인한 공식 내려받기: 벤처 유형별 제출서류 가이드라인 PDF 4종·인건비 산정내역서 양식(HWP), 이노비즈 제출서류 가이드라인 PDF, 연구소 신청 서식(시행규칙 별지)
- 이 개발 환경에서 열리지 않은 발급처(홈택스·인터넷등기소·4대보험)는 **'접속 미검증'** 표시 → 배포 전 대표님 브라우저 확인 1회

## 3. 레드팀 질문 (v2 설계 기준)

| 질문 | 판정 | 설계상 장치 |
|---|---|---|
| 구간 버튼 때문에 판정이 틀어지지 않나? | 막음 | 칩 경계 = 공식 기준값, 기준이 업종별로 다르면 동적 질문 1개로 |
| 확률·점수로 오해되지 않나? | 막음 | %·점수·난이도·비용 없음, "기본요건 충족/미충족/확인 필요"만 |
| 신청 가능=취득으로 읽히지 않나? | 막음 | "기본요건" 용어 + 다음 단계 '기관 평가' 명시 |
| 모름을 미충족으로 처리하지 않나? | 막음 | 엔진 4값 로직 유지(회귀 테스트) |
| 링크가 죽거나 바뀌면? | 완화 | 확인일 표기, 6개월 재확인, CI에서 링크 점검 추가 예정 |
| 120개로 늘리면 품질이 떨어지지 않나? | 완화 | 등급 A/B/C 명시, 미검증은 정보 안내로만 |
| 상담 버튼이 가짜 접수가 되지 않나? | 막음 | 전화·메일 실링크만(LeanDiag식 가짜 '접수 완료' 없음) |
| PDF와 화면이 다르지 않나? | 막음 | 같은 데이터로 생성(기존 구조 유지) + PDF 검사 |

## 4. 남은 위험(구현 때 처리)
- 화면이 길어지는 문제: 신청서류는 탭 안에만, 모바일은 접기 기본
- 70~120개 인증의 공식 링크 유지: 링크 점검 스크립트를 CI에 추가
- '문서 수정·HTML 저장'으로 고친 보고서는 진단 원본과 다를 수 있음 → 표지에 "편집본" 자동 표시
