## 3. v2 고객 여정 (확정: 3단계 · 한 장 카드)

```
[홈] 한 줄 카피 + "무료 진단 시작" 1개
 └ 1 인증 고르기    카드 그리드(국내/해외 탭·분야 필터·검색) · 최대 3개 · "잘 모르겠어요 → 추천받기"(질문 3개로 후보 제시)
 └ 2 우리 회사 답하기  공통 칩 5~6개 + 고른 인증에 필요한 칩만 아래에 이어서(인증별 소제목) · 모두 '모름' 가능
 └ 3 결과·할 일      인증별 결과 카드(요건 N/M · 준비서류 수 · 유효기간·신청처) → 탭[요건|서류|할 일 로드맵] → PDF·상담
```
- 예상 소요 1~2분. 2단계는 한 화면이지만 답한 칩은 접히고 다음 질문으로 자동 스크롤
- 이하 '5단계 안'은 비교용으로 남김

### (참고) 처음 제안한 5단계 안

```
[홈] 한 줄 카피 + "무료 진단 시작" 버튼 1개  (검색은 1단계 안으로)
 └ 1 인증 선택   카드 그리드(국내/해외 탭 + 검색) · 최대 3개 · "잘 모르겠어요 → 추천받기"
 └ 2 회사 정보   칩 6개: 사업자 형태 / 업력 / 규모 / 업종 / 목표 시장 / 보유 현황(연구소·벤처·특허)
 └ 3 인증별 확인 고른 인증에 필요한 것만, 칩으로 (보통 3~6개)
 └ 4 진단 결과   인증별 결과 카드(✓/✕/? 체크리스트) · 서류 · PDF
 └ 5 로드맵·상담 3단계 로드맵 + 상담 시 준비할 것 + 전화·메일
```

- 예상 소요: 1~2분(현재 5분 이상). 질문 수: 벤처 1개 기준 **약 10개 → 전부 탭으로 답변**
- 모든 칩에 '모름' 포함. 모르면 결과에 "이것만 확인하면 판정돼요"로 1줄 안내
- 뒤로 가기·답 수정 시 결과 즉시 재계산(카드 안에서)

### 숫자 입력 → 구간 칩 (판정 정확도 유지 방법)
공식 기준값을 칩 경계로 써서, 숫자 없이도 판정이 정확해요.

| 질문 | v1 | v2 칩 |
|---|---|---|
| 설립일 | 날짜 입력 | 업력 `1년 미만 / 1~3년 / 3년 이상 / 예비창업 / 모름` (3년 경계 근처일 때만 날짜 추가 질문) |
| 투자금 | 만원 입력 | `받은 적 없음 / 5천만원 미만 / 5천만원 이상 / 모름` + 자본금 대비 `10% 이상 / 미만 / 모름` |
| R&D비 | 만원 입력 | `5천만원 미만 / 이상 / 모름` + 매출 대비 비율 `5% 미만 / 5~8% / 8~10% / 10% 이상 / 모름`(업종별 기준 자동 적용) |
| 부채비율 | % 입력 | `1,000% 미만 / 이상 / 자본잠식 / 모름` |
| 연구인력 | 명 입력 | `0 / 1 / 2 / 3~4 / 5~6 / 7~9 / 10명 이상 / 모름` (규모별 기준 2·3·5·7·10명이 경계) |

→ 엔진은 그대로 두고 '구간 답'을 받는 판정 함수만 추가(경계가 걸치면 '확인 필요').

## 8. 인증 확대 방안 (현재 22개 → 1차 70개 내외)

### 8-1. 원칙: '많이 보여 주되, 판정은 근거만큼만'
| 등급 | 화면 표시 | 기준 | 현재 → 목표 |
|---|---|---|---|
| **A. 자동 판정** | ✓/✕/? 요건 판정 | 공식 원문(법령·고시·운영규정)에서 요건을 뽑아 규칙화 + 숫자 대조 테스트 | 5 → 10 |
| **B. 요건 체크** | 핵심 요건 3~6개 자가 체크(판정 대신 '확인 목록') | 공식 기관 안내 화면에서 대상·요건 요약 확인 | 0 → 25 |
| **C. 정보 안내** | 무엇·언제·누가·어디서 + 공식 링크 | 공식 기관·링크 접속 확인 | 17 → 35 |

→ 검색·추천에는 70개가 모두 나오고, 결과 카드는 등급에 맞는 방식으로 보여 줘요. 확인 안 된 내용은 지금처럼 '확인 필요'로 명시해요.

## 10. Claude API 활용안 (서버 경유·선택 기능)

### 10-1. 쓰는 곳 3가지
| # | 기능 | 사용자 | 결과물 | 안전장치 |
|---|---|---|---|---|
| ① | **목록에 없는 인증 정보 카드** | 고객 | 무엇·언제·누가·공식 신청처·확인할 요건 3~5개 | 'AI 초안 · 공식 확인 필요' 배지, 판정·확률·비용 생성 금지, 공식 기관 도메인만 웹 검색 |
| ② | **결과 쉬운 말 해설** | 고객 | 진단 결과를 대표 눈높이 3~5문장으로 | 엔진 결과(JSON)만 입력, 새 사실 생성 금지(검증 후 불일치 시 해설 숨김) |
| ③ | **운영자용 신규 인증 등록 초안** | 운영자(대표) | 카탈로그 JSON 초안 + 근거 URL·발췌 | 사람 검토 전엔 `UNVERIFIED`(정보 안내)로만 공개. 자동 판정 규칙은 여전히 원문 대조 + 테스트 필수 |

→ ③을 쓰면 인증 확대(§8)를 **주 단위로 빠르게** 늘릴 수 있어요. ①은 고객이 어떤 인증을 입력해도 빈손으로 나가지 않게 해 줘요.

### 10-2. 기술 구성 (기존 PSF·재무 진단과 같은 방식)
- 위치: `certification/netlify/functions/` (서버). **API 키는 Netlify 환경변수에만**, 브라우저에 없음
- 모델: `claude-opus-5-5`(저장소 기존 앱과 동일). 해설(②)은 effort `low`, 정보 카드(①)는 `medium`, 운영자 초안(③)은 `high`
- 출력: **구조화 출력(JSON 스키마)** — 화면에 그대로 꽂히는 필드만 받음, 스키마 밖 내용 버림
- 웹 검색: 서버 도구 `web_search` + `web_fetch`, **허용 도메인 목록**(go.kr·or.kr 공공기관, iso.org, europa.eu, fda.gov, fcc.gov 등)으로 제한, 결과마다 출처 URL 필수
- 거절·장애 대비: 서버 측 대체 모델(fallback) 설정, 실패 시 기존 정보 카드/규칙 해설로 자동 대체(기능 없이도 앱은 정상 동작)
- 개인정보: ①③은 회사 정보 미전송. ②는 회사명 제외·구간값만 전송, **사용 전 동의 1회**. 개인정보 안내 페이지 갱신 필요

### 10-3. 비용 감(참고, 실측 전)
- 단가: 입력 100만 토큰당 $4 · 출력 100만 토큰당 $20(claude-opus-5-5 기준) + 웹 검색 사용료 별도
- ② 해설 1회 ≈ 입력 3천·출력 6백 토큰 → **약 2~3센트**
- ① 정보 카드 1회(웹 검색 포함) ≈ **수십 센트 수준** — 같은 인증은 결과를 저장해 재사용
- 실제 비용은 시범 운영 1주 측정 후 확정, 월 상한(예: $50) 설정 권장
- 더 저렴한 모델(Sonnet·Haiku) 전환은 품질 비교 후 대표님 결정 사항
